- 不开展多账号、分页采集、风控规避、概率伪装、模拟真人或额外平台互动功能。

## 3. 数据不变量

1. BV/AV全局去重跨频道、跨重启有效；重复搜索不创建计划、不抽动作、不改日期。
2. 发现与计划原子提交；模板缺失或失败回滚不能永久占用去重。
3. 原动作、首次入池时间及创建时模板候选池不可被后续配置修改覆盖；人工更新任务快照需明确操作、版本校验和留痕。
4. 计划与尝试分离；每次发送都有独立历史，不能用 UPDATE 覆盖先前失败、额度或回执。
5. 发送前 claim、正文、目标、effective_action、attempt 和间隔持久化；每计划只允许一个在途尝试；同数据库只允许一个活动调度实例。
6. 日容量预留不是实际发送额度；实际claim必须原子核查全局、动作、频道、逾期份额和最短间隔。
7. confirmed failure、uncertain、永久错误、读取失败、未执行等待必须分清；不确定默认进入人工核查，不靠错误文案猜测“肯定没发”。
8. 重启暂停；遗留claimed转uncertain；取消、暂停和配置变更在异步回调后及claim前再复核。
9. 人工确认与后台回执通过状态版本/条件更新保护；除可信成功证据外，过期回调不得覆盖新的人工状态。可信成功按第17条归档并终结计划；确认成功不能安排第二次发送。
10. 迁移版本化、事务化、幂等；不清空真实数据；旧failed缺少确定性证据不得自动重试。
11. 不匹配结果不写视频级记录；必要搜索级统计不得包含这些视频的标识或内容。

12. attempt计费字段quota_day、dispatch_class、effective_action、频道和发送UID在claim时确定且不可变；历史计数不能关联计划当前周期重新分类；额度下调保留已用。
13. 独占锁先于Store初始化、迁移和恢复；启动失败的第二实例不能修改状态。不凭TTL接管活实例，锁覆盖整个数据库实例生命周期。
14. 数据库绑定验证UID；UID未知或不同则暂停，不能自动移交旧任务/清空额度。迁移历史未知UID如实保留，不能倒填当前账号。
15. 准备读取失败用计划事件留痕并更新一次周期，不伪造写attempt；读取预算/next_prepare_at持久化，等待额度不能每tick重新读取。
16. 任务取消、频道删除和停用只阻止未来写，不把在途claimed直接转成未发送取消；必须按开发计划状态表归档实际结果。
17. 客户端超时、关闭桥接或看不到评论均不证明远端未发；重排uncertain前必须满足原请求结束屏障及未发送证据。迟到成功永远归档原attempt，不能因CAS冲突丢弃。
18. 旧库迁移保留可确定的当日已用额度；未知计费类别保守显示并计入总额度及逾期已用份额，不能以迁移为由重置。

## 4. 调度与动作不变量

- 新自动流程只做视频标题关键词匹配，不使用时间、播放量、简介或旧AI分流筛选；视频字段格式校验、权限判断和账号安全检查仍保留。
- 70%延后、20%评论、10%回复；延后80%评论、20%回复。概率只在计划创建时确定一次，不能用重试重新抽签补偿分布。
- 自然日按Asia/Shanghai；日期函数必须可注入时间测试。首次周期D+1…D+30；重试周期以实际确认失败日为D。
- 风控/未登录全局暂停等待人工；搜索/例行登录错误不批量重排所有计划；恢复不以恢复日重置周期。
- 回复对象执行时重选；仅结构可靠的成功空候选集合可降级；原动作保留，实际评论使用评论模板快照及评论额度。
- 未来日不提前执行；30天已满落到D+30标溢出，不虚构容量、不丢弃任务。
- 50%逾期上限按计划定义，奇数额度日期交替取整；重启不能增加份额；剩余逾期名额可给普通任务，反向不借用。
- 队首受限不能阻塞所有任务；禁止持续重抽正文、日期或动作来绕过限制。
- 视频删除、评论关闭、无效内容等明确永久错误转人工状态；不把权限限制当普通临时错误反复请求。

## 5. 安全与开发环境

- 实际服务、桥接子进程及开发/测试/Review/QA的启动环境保持 `BILIBILI_WRITES_ENABLED=false`；真登录、真实评论、真实AI调用不属于自动验收。
- 唯一测试例外：完全Mock视频读取、SDK写入、凭据加载且网络禁止的进程内单元测试，可在受控夹具中临时patch模拟true以覆盖写路径；测试结束/异常时恢复环境。任何漏Mock的网络调用立即失败；例外不适用于真实桥接子进程、服务或账号。
- 使用Fake Bilibili、假桥接响应、内存/临时SQLite和临时DATA_DIR；不用真实Cookie、API key、账号、数据库和备份做夹具。
- 不读取或打印私有data/.env/凭据；日志、测试输出、API响应、Markdown和Git提交不得包含密钥或Cookie。
- HTTP 403/412、验证码和风控仍失败关闭；不改变真实写锁、不自动解锁、不绕过平台限制。
- 保留127.0.0.1绑定、Host/Origin守卫、CSRF限制和前端密钥不回显。
- 不修改固定vendor源码；bridge适配保留原27工具名称和参数契约。取消搜索日期限制通过调用不传日期完成，兼容独立手动工具的日期参数。
- 不升级依赖或锁文件以顺带解决实现问题；确需新依赖先说明必要性并核实锁定API。
- 发送错误适配优先结构化结果：保留脱敏原始平台码、操作阶段、是否可能已提交；未知证据不得降级为“可重试”。

## 6. 代码与界面

- 沿用严格TypeScript、ESM、后端`.js`导入、Zod共享schema和node:test，不引入第二套测试框架。
- 排程、匹配与状态计算尽量提取纯函数；随机数/时钟可注入，不使用真实sleep验证30天行为。
- 数据库事务内不做网络请求；网络返回后重新复核；状态变更使用版本或条件UPDATE，不能无条件覆盖。
- 页面使用中文状态、分页与筛选；按钮具有加载/禁用/错误反馈；失败不丢用户输入，在途响应不覆盖新编辑。
- 删去无效过滤/AI分流选项；原计划动作与实际动作分别展示；“日期预留”“确认失败”“结果不确定”“容量溢出”用明确中文解释。
- 新表结构向前迁移，旧程序不能继续操作升级库。只有升级后没有新增写尝试时，才允许直接恢复迁移前一致性备份；已有尝试必须先保存并验证合并新增成功/失败/uncertain、去重与额度账本，无法合并则向前修复且禁止回滚后自动发送。不得只复制运行中WAL数据库主文件当备份。

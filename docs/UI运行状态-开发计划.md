## 1. 目标、范围和完成定义

首页用最少信息回答：现在在做什么、搜索与互动各自下一步是什么、为什么要等、何时可再尝试、是否需要用户操作。

默认可见信息限定为：
1. 一句主状态与必要的等待原因；
2. 搜索、互动各一行的下一次安排；
3. 有问题才出现的“需要处理”卡片及直接入口；
4. 今日已完成评论/回复、待处理数量和最多三条近期计划。

网络操作进行中才显示“已等待 N 秒”；普通等待不再显示阶段秒表。“已到执行时间”与“超过30天未完成”分开；不在名为“倒计时”的栏位内显示负数或“已到期一天”。

本次不改变：关键词、排序/页数、概率、模板快照、30天周期、任务选择顺序/数量窗口、额度、回复回退、错误恢复、claim/attempt 或实际发送次数。唯一下列明确例外是S0a的启动/暂停控制竞态修复，单独阶段、单独提交；其余业务缺陷单列，不借展示改造修复。

完成定义：由确定性测试证明展示与当前执行判定一致，页面能直接进入核查任务；断线/旧后端/不确定结果不伪装成正常运行；不需要真实账号测试。

## 3. 信息模型：事实、安排和原因分开

### 3.1 单一展示快照

扩展 `/api/state`，保留原字段，新增有版本的 `display` 对象（具体Zod契约在阶段1定稿）。由服务端同步读取、纯函数推导，返回：
- `schemaVersion`、`instanceId`、`snapshotSeq`、`serverNow`：识别重启、乱序和时间基准；seq为进程内快照序号，不写库。
- `control`：running/pauseRequested/writesEnabled、明确暂停/启动中状态；各控制请求的顺序以服务端接收顺序为准。
- `operation`：当前操作id、业务种类、开始时间、频道/计划id与安全标题；请求本地等待预算可空。
- `search` / `interaction`：各自的状态、主阻塞原因、完整原因列表、时间种类、最早可尝试/下次检查时间、候选摘要（不保证发送）。
- `attention`：需要处理的总数、按类别/影响范围的计数、最少必要任务摘要、服务端允许的操作类型。
- `upcoming`：最多3条近期未完成任务（计划id、标题、动作、普通/延后、当前排程时间currentDueAt、当前解释）；独立于旧plans前200条。
- `totals`：今日发起且当前确认成功，按实际动作分组、待处理/待核实/发送中。继续把attempt当额度计费依据，不能把attempt计数用作已成功数。

“在线/无法连接/状态过期/版本不兼容”由浏览器连接层表达，服务端不能用字段宣称自己离线。显示数据不得包含Cookie、API key、模板正文、账号凭据或整个桥接响应；计划详情沿用既有授权接口。

### 3.2 两个通道的解释必须与执行一致

搜索通道：启用频道、nextSearch、搜索额度、readRetryAt、当前串行操作与全局暂停。预算未满时，时间下限为 max(频道nextSearch、readRetryAt、now)；当日预算满按上海次日日界显示“最早再检查额度”。额度配置为0则显示等待配置，不给虚假恢复倒计时。

互动通道：全局暂停/写锁、当前操作、未确认结束的原请求、retryAt、nextInteraction，以及计划dueAt、nextPrepareAt、频道/归属/取消、实际动作可用额度、准备读取预算、快照和人工状态。

仅对无人工阻塞且已知的时间门槛取 max；回复对象和有效动作尚未确定时，只承诺“再次检查/准备回复”，不声称必发回复或必发评论。新搜索可能产生更早候选，因此显示“基于当前已知计划”。只读预测不得调用带写入的方法或B站接口。

时间语义使用以下类别，而不是一个万能 at：
- `scheduled`：当前持久化dueAt（currentDueAt），仅说明现有安排；该字段可能被额度等待或新周期覆盖，不冒充首次历史安排；
- `eligible`：满足已知时间门槛后最早可尝试，仍需发送前复核；
- `check`：再次检查额度/读取/原请求结果的时间；
- `unknown` / `manual`：不能推算，不显示倒计时。

API提供所有已判定有效阻塞原因，首页只展示一个主原因与必要的次要说明，其余在详情展开；主文案选择范围最强且影响本通道的一项。为另一个通道保留自己的解释，不能用 readRetryAt 抹掉可发送互动。多任务按实际窗口与排序进行候选解释，不根据“最旧dueAt”作承诺。

### 3.3 执行判断的复用与边界

优先把现有只读额度判定提炼为返回 reasonCode/nextCheckAt 的纯方法，由 canClaimNow 等原调用位置复用；布尔结果必须与原实现一致。beginPlanPreparation 中的日预算可以增加独立只读镜像或抽取共同计算，但禁止在读取状态时调用原方法。

不把 `/api/state` 变成新的调度器：不重排dueAt、不清除退避、不消费读取预算、不改变版本、不绑定账号、不写Activity。

到期扫描前100条若全部因冷却而不能处理，但第101条可处理：本次只如实说明“当前调度批次受限，后续候选尚未选中”，绝不能承诺发送第101条。报告为已知调度限制；修复窗口需要独立任务及授权。

### 3.4 不确定结果的影响范围

- 与现有Store.anyRequestInFlight()一致，对任意attempt存在requestInFlight=true（不限最新attempt），或当前发送尚未确认结束：其他写入受阻；搜索若执行条件允许可继续。说明是“原请求结束尚未确认”，不能伪称已观察到远端仍在运行。
- uncertain 且 requestInFlight=false：该任务不自动重发；其他任务依原规则继续。显示“此条需要核实”，不默认全局停止。
- retryAt 尚未来到：如实说明回执轮询也被现有互动退避阻止；不声称后台正在持续核查。
- 请求结束证据未知、日志not_found、服务重启claimed->uncertain：沿用安全屏障，不清标志或自动标记未发送。

## 4. 首页与处理流程

主卡片：一行状态＋一句原因；正在请求时显示“已等待 N秒”，默认不显示等待阶段秒表。严格优先级如下，暂停是控制状态，当前操作是事实，两者必要时同时可见。

| 优先级 | 条件 | 主状态/双通道规则 |
|---|---|---|
| 1 | 连接失败、快照过期、版本不兼容 | 无法确认实时状态；旧事实标注为历史，停止执行承诺 |
| 2 | 已请求暂停但实际操作尚未结束 | 暂停中，正在等待当前操作结束；显示该操作耗时，不伪称已停止 |
| 3 | 当前确有本地操作且未要求暂停 | 正在搜索/读取/发送/检查；只显示真实操作，不把串行安排说成同时执行 |
| 4 | 当前控制状态暂停且无实际操作 | 已暂停＋结构化原因；两通道不显示自动恢复承诺 |
| 5 | 人工/配置阻塞 | 只有受阻通道被标为等待处理；另一通道保持自己的安排；单条核查只进处理卡 |
| 6 | 仅时间门槛 | 基于两通道给出最近可解释安排；互动因冷却等受阻要写清原因 |
| 7 | 无已知动作、无待处理 | 空闲＋无任务/无启用频道等准确原因 |

其下两行：
- 下一次搜索：时间/原因＋关键词或频道；
- 视频互动：时间/原因＋当前候选动作。

“有11条计划已到执行时间，当前等待发送间隔；还需04:32”替代“等待计划到期/已到期一天”。如果原因未知，就显示“正在确认调度状态”，不能制造原因。

“需要处理”卡片提供“去核实/去登录/补充模板”入口。不确定事项打开 `/plans?state=uncertain&planId=…`；同一路径支持刷新、前进后退、复制和跨页id加载。直接请求详情，不要求id在当前50条页内。核查详情包含原attempt信息、前往B站核对链接和现有人工动作；无回执/页面看不到评论不是未发送证据。requestInFlight=true时解释按钮限制，不新增清标志或强制重发入口。

未来计划显示“今天/明天的具体计划时间”，来源是当前dueAt，不新增“首次排程时间”。额度或失败周期已覆盖dueAt时如实展示当前安排；需显示历史时间时只用已有证据，证据不足写未知。普通到期显示“已到执行时间＋未执行原因”。超过周期截止显示“超过30天未完成，按现有逾期优先规则处理”，不更改配额。

总览统计：今日已完成评论/回复、待处理、需核实。成功的日归属沿用现有startedAt的Asia/Shanghai自然日，必须status=succeeded且按effectiveAction分组；不是按回执到达日或人工确认日。前一日发起、次日确认的结果记回发起日且不重计。尝试数/逾期份额/容量保留在详情。状态必须有文字/图标，不能只靠颜色；窄屏不挤压处理按钮。

## 5. 时间、连接与一致性

- 每次快照以服务端毫秒时间和本地 performance.now 建立锚点，1秒本地重绘；轮询约5秒，前台最长合理新鲜度15秒。系统时钟跳动不直接改变倒计时。
- 状态请求同一时刻最多一个，5秒网络等待上限；立即进入“连接异常/状态未更新”，保留旧数据但标注过期并冻结可执行承诺；可按现状允许明确的安全暂停，禁用新的启动/核查/修改操作直到新鲜状态恢复。
- 标签页隐藏时可降低轮询；恢复可见/窗口聚焦立即刷新，拿到新快照前先显示正在更新。重绘使用当前单调时间，不逐秒扣减状态。
- 丢弃过期请求；按instanceId切换清旧锚点，按snapshotSeq拒绝同实例旧快照。旧实例的迟到响应不能覆盖新实例；服务端重启由新请求的响应确立。
- 原始snapshotSeq仅表示观测次序，不替代计划version或人工动作证据。详情请求采用自己的序号/abort，不能覆盖用户已编辑模板草稿。
- 全部业务绝对时间明确标注北京时间，使用固定Asia/Shanghai格式化；浏览器在洛杉矶或更改时区仍不得改变额度日和计划日。
- 不能给MCP connect+tool整个步骤固定45秒保证。没有可证实的请求截止就只显示已等待；若展示tool预算，文案为“调用等待上限，不代表远端已停止”。本次不修改MCP连接/发送超时设置。

## 7. 验收与回退

自动化门槛见测试文档；新增用例不能skip。既有55项跳过是历史记录，实施时重新记录实际数量，不能声明它们已通过。纯文档阶段不需要运行构建或接触真实数据。

本机UI验收只用临时SQLite、Fake Bilibili和独立loopback端口；真实环境变量BILIBILI_WRITES_ENABLED始终false。装配分为三种，不能混称：

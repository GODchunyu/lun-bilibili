## 1. 目标与范围

实现本地关键词匹配、持久化分流、30 天延后排程、失败历史、逾期额度、模板快照和旧数据迁移。保留单账号、单机、本机网页的部署架构。

搜索仍按现有关键词轮换、随机搜索间隔、第一页最多 50 条、播放量排序执行；发布时间与播放量只作为平台返回字段，不参与资格过滤。搜索仍只覆盖平台返回的第一页，不保证覆盖所有匹配视频，也不保证持续发现新视频。界面增加本次返回数、匹配数、重复数和新增计划数，使反复返回旧视频可被看见。分页、换排序和扩大抓取范围不纳入本次改造。

AI 不参与本次自动巡逻的匹配、概率分流或撰写。保留其他独立 AI 能力和配置的兼容性；新巡逻流程不因旧 `aiJudgment` 设置或缺少模型密钥而改变行为、暂停或调用模型。界面不再提供会覆盖本流程的 AI 分流开关。

不修改安装方式、端口、真实账号数据和当前运行中的服务；本轮未发布、未推送、未进行真实互动验收。

数据库绑定一个经过登录验证的账号 UID。新计划保存所属 UID，实际尝试保存经过发送前验证的 UID。登录缺少 UID 或与数据库绑定不一致时暂停，不建立新计划、不发送旧任务、不自动重新绑定、不清空额度；更换 Cookie/扫码后必须重新验证。恢复同一 UID 可继续原任务，其他账号需要独立数据目录，不在本次开发多账号共享队列。旧记录归属未知时保留 unknown 标记，待人工核查；不能把当前登录用户假称为历史发送者。

## 2. 业务规则与计算口径

### 2.1 匹配与创建计划

1. 本地匹配只检查视频标题；UP 主名称和简介均不参与匹配。
2. 针对当前搜索频道的全部关键词，只要任意一个命中视频标题即匹配；不检查 UP 主名称。
3. 解码搜索标题的 HTML 实体，去除搜索高亮标签，使用 NFKC 归一化、统一大小写，并忽略 Unicode 空白及标点。符号和 emoji 不自动当作标点删除。
4. 中文或中英混合关键词采用规范化后的子串匹配。纯英文/数字关键词额外要求词边界：按归一化后、去标点空白前的 ASCII 字母数字词段检查连续完整词段；允许 `ca t` / `ＣＡＴ` / `cat!` 命中 `cat`，不允许 `concatenate` 命中 `cat`，也不允许 `12345` 命中 `123`。该边界规则避免短英文/数字误匹配。
5. 规范化后为空的关键词拒绝保存；单字符关键词允许但显示误匹配提示。等价关键词本地合并用于匹配，不擅自改写搜索关键词原文。
6. 不匹配结果不创建发现、视频日志或互动计划；可以记录不含 BVID/标题/UP 主的搜索级汇总计数。匹配过程中允许内存暂存，禁止以视频为键持久化不匹配数据。
7. BV 与 AV 均跨频道持久化去重。成功互动、结果不确定、有效计划和明确取消计划均阻止自动创建第二份计划。
8. 未具备可用模板的频道不得启用。即使配置在请求期间改变，也不允许“只占用去重、未建立计划”的半完成状态：发现记录、计划、动作和模板快照在同一个事务中提交。
9. 同一视频命中多个频道时，保留第一个成功创建的计划；频道尚未匹配、已停用或模板缺失均不能提前占用 BVID。这里保留现有搜索顺序，不另建全频道匹配收集器。

### 2.2 分流与快照

| 初次随机值 r（0≤r<1） | 分流 | 动作 |
| --- | --- | --- |
| 0≤r<0.70 | 延后 | 再抽一次：0≤r<0.80 评论，其余回复 |
| 0.70≤r<0.90 | 即时队列 | 评论 |
| 0.90≤r<1 | 即时队列 | 回复 |

“即时”仍需遵守发送间隔和每日额度，并不表示搜索后立即请求发送。70% 是延后分流，不能再命名为永久跳过。只有成功创建新计划时才产生一次固定分流；重搜、重启、改配置和重试均不重新抽取动作。

所有新计划（含即时队列）均在创建时保存频道名称、搜索关键词、实际命中关键词/字段、视频快照、评论与回复模板快照、原计划动作、创建时间、周期起点和计划日期。选择的是入池时启用模板；不依赖后续模板表的正文或存在性。

评论和回复模板快照必须各至少有一个；采用候选池快照，在发送时从该池选择与上一条不同的正文，并在 claim 时保存实际正文。快照内容固定，选取正文不改变动作概率。仅有相同正文可用时保持任务为“等待可发送模板”，不概率跳过、不默默改正文；其他任务仍可执行。用户可明确更新该任务快照或取消任务，操作需留痕。

### 2.3 日期、容量与逾期

日界固定 Asia/Shanghai。D 是入池或明确失败当天；30 天指 D+1 到 D+30 的自然日，不采用日历月长度。首次入池时间永久保存，每次失败只更新本轮周期起点与截止日。

延后日期在事务中按照未来 30 天的剩余全局、动作和频道预留容量选择：先选占用比例最低的可用日，再在同负载日中随机抽取。保存结果，重启不重抽。排程只预留容量，发送前按实际发送尝试再次校验，不承诺服务器离线期间完成任务。

即时任务、延后任务、重试任务共享同一容量账本。配置变化、实际失败占额、任务取消和回复降级会释放/调整预留；不能因为重新排程将同一任务计算两次。容量降低后，先保留较早计划，超额计划向后移动；本轮截止日不变。

未来 30 天没有可用日时，安排到 D+30，标记容量溢出，不虚构空闲名额。D+30 当天容量溢出任务即可进入逾期类别；其他任务在本轮截止日之后进入逾期类别。错过计划日但尚未到截止日的任务属于普通到期积压，先于尚未到期任务，但不提前占用逾期专用额度。

逾期任务最多占每日全局互动尝试额度的 50%，仍受实际评论/回复和频道额度限制。奇数总额度无法每天精确对半：按固定 Asia/Shanghai 日期序号交替取上整/下整，在总额度不变时两个相邻自然日合计为 50%；每日上限不因重启改变。总额度为 1 时隔日提供一个逾期名额，总额度为 0 时均不发送。

新尝试claim 时必须把 `quota_day`（Asia/Shanghai 日期）、`dispatch_class`（ordinary/overdue）、`effective_action`、频道计费归属、实际账号 UID 与 `attempt_id` 一起持久化，计费字段不可变。迁移时无法确定旧计费类别的尝试使用 `legacy_unknown`，仅用于历史迁移，新claim不得使用此值；查询时保守计入当日总额度及逾期已用份额，界面仍显示“旧分类未知”，不能声称是已知逾期。历史额度只查询 attempt 的这些字段，不能关联计划当前周期/当前状态重新分类。逾期失败进入新周期后，当日已用逾期名额仍然已用。限额下调后剩余额度为 `max(0, 新上限－对应已用尝试数)`；已用数不得删除、重置或因重新登录/取消任务/更新配置而变化。

逾期类别优先于普通类别：先按本轮逾期天数，再按相同截止日的频道轮询和计划 ID 排序。逾期名额不足时不借用普通类别名额；逾期任务不足时，其未使用名额可供普通任务使用。普通类别中先到期、先安排；不提前执行未来日期的任务来填额度。

如果队首因频道停用、动作额度不足或模板缺失而不能执行，应查找后续符合条件的到期计划，禁止队首堵住全队列。批量检查有上限且保存游标，避免每秒无边界扫描。

持续新增计划量大于处理能力时，队列仍会增长；不承诺仅靠排程保证 30 天全部完成。按无降级、无失败估算，每 N 个新匹配视频最终约产生 0.76N 评论与 0.24N 回复。仪表盘显示最近实际新增/处理速度、预计积压、容量溢出和最早逾期，并允许人工暂停搜索/取消选定任务；不擅自增加额度、删除任务或改变概率。

### 2.4 执行动作

回复执行时重新读取评论，沿用当前普通评论安全筛选，排除置顶、本人、无有效 ID 及元数据不明确的评论。当前桥接只读取第一页最多 30 条、按点赞排序，因此“没有合格对象”表示这次可用返回集合中没有对象，不代表全视频没有评论。

只有成功取得、且结构完整可验证的评论结果中没有合格对象，才能降级为评论。读取失败、超时、畸形返回不能当空列表。原 `planned_action=reply` 保留；本次 `effective_action=comment` 和降级原因记录到尝试。

降级按评论额度校验，不能占用回复额度发送评论。评论额度不足时保留原动作并重新安排，不计发送失败、不增加发送尝试次数；下一次仍重新读取回复对象。降级评论明确失败后进入新周期，下一周期依然以原回复动作选择对象。

准备读取受独立持久化节流控制：计划保存 `next_prepare_at` 和当天读取数，每计划每自然日最多 3 次评论准备读取，全局评论准备读取最多为当天总互动额度的 3 倍；总额度为 0 时不读取评论。没有实际发送额度的动作不反复读取；成功读取后因降级评论额度不足而等待时，下一次准备默认不早于次日额度恢复，或在用户调整额度后事件唤醒。事件唤醒不清零读取次数，也不绕过读取预算/退避/最短准备间隔（沿用 waitMin）。频道暂停、模板等待和人工状态不主动读取；后续合格评论任务仍可执行。读取预算是请求保护，不改变动作/失败周期，也不概率丢弃任务。

收到成功回执则完成计划，即使回执可选封面/统计字段格式异常也不得改为失败。后来评论被删除不自动重发；人工删除平台评论也不解除全局去重。

### 2.5 失败与人工恢复

| 情况 | 任务处理 | 系统处理 |
| --- | --- | --- |
| 确认未发送的普通/API 失败 | 记录失败；以失败日 D 重新安排 D+1…D+30；保留原动作和快照 | 现有独立退避、连续失败阈值继续生效 |
| 评论准备读取失败或结构异常，且未进入写入阶段 | 记录独立 preparation_failed 事件，保留回复动作；以失败日 D 重新安排下一周期；不创建写 attempt、不占写额度 | 读取失败计数/退避生效；risk/auth 同时全局暂停 |
| 风控/未登录且确认未发送 | 如错误属于正在处理的计划，为该计划记录失败并确定新周期 | 全局暂停，人工处理并手动启动 |
| 搜索或例行登录检查风控/未登录 | 不批量重排未处理任务；只记录系统事件 | 全局暂停 |
| 请求可能已提交后的超时、断连、进程崩溃、不可判定响应 | `uncertain`；不自动重试 | 界面提示人工核查 |
| 视频删除、私密、评论关闭、永久拒绝或正文不合法等明确不可恢复情况 | `manual_review`；保留计划与原因，不无限自动请求 | 人工修改快照、取消或明确重新安排 |
| 容量不足、频道停用、快照正文与上一条相同 | 等待/重新排程，不算发送失败 | 不绕过额度、频道或间隔 |

安全判定优先级：存在可能已提交的证据时结果不确定优先于自动重试；遇到风控/未登录同时必须全局暂停。不能把所有网络错误都映射为可重试 API 失败。

重试日期只在记录确认失败时生成一次并持久化。人工恢复不以恢复日刷新周期；若原计划日期已经过去，恢复后作为到期任务依额度处理；若原周期已过则进入逾期类别。全局暂停期间其他任务维持原日期。

本轮失败一次即可安排下一周期；保留每次失败、原始脱敏平台码、失败阶段和周期数。连续明确失败达到 3 次标为“高失败任务”并提示，不自动删除、不因为提示自动取消。永久错误和不确定结果进入人工状态，避免无限网络重试。

读取准备失败也属于该计划的一次已确认未发送失败，增加计划失败次数，并只生成一次新周期事件；其错误历史存入计划事件而不是伪造写 attempt。搜索与例行登录失败不算某个计划的失败。

额度按实际写请求的保守尝试计数：发送前原子 claim 并持久化额度与间隔；claim 后崩溃保守占额。仅搜索、读取评论失败、无对象、容量推迟不占评论/回复额度，另记录读取失败。发送明确失败和 uncertain 均占额。

人工处理 uncertain 必须先核查：确认已发则标记成功并保存已知回执；确认未发才可重新安排；无法确认则保持 uncertain 或取消。人工操作均留痕，不提供默认一键重发。

客户端超时不等于 Python/平台请求结束。每次写操作要有可关联的 operation/attempt 标识和原请求未决状态。原桥接写调用尚未结束时，人工“确认未发并重排”必须被拒绝；需先建立本地请求结束/排空屏障，并有明确远端未发送证据。停止桥接、达到时间阈值或暂未看到评论都不能单独证明远端未发表，仍按 uncertain 处理。核查不了就保持 uncertain 或取消未来尝试，不放开重发。

迟到回执始终关联原 attempt 归档。可信成功证据不因取消、删除频道、版本变化或人工状态而丢弃；成功终结该计划、阻止后续尝试，界面显示实际发送事实。若发现后续尝试已在途，立即暂停并转人工核查，禁止继续开始写入。版本校验用于拒绝冲突转移，不能代替平台请求结束屏障，也不能忽略已发生的成功。

## 3. 数据设计与迁移

保留 `discoveries` 作为已成功建立计划/历史去重信息，增加 schema 版本和事务迁移。

| 实体 | 必要字段/约束 |
| --- | --- |
| `interaction_plans` | 唯一 BVID/AV 关联、owner_uid、来源类别、频道 ID/名称快照、视频/关键词/命中信息、planned_action、评论/回复候选池快照、first_enqueued_at、cycle_start_day、cycle_deadline_day、due_at、overflow、cycle_count、failure_count、state、version、next_prepare_at、read_day/read_count、channel_disabled、orphaned、cancel_requested及必要恢复状态 |
| `interaction_attempts` | plan_id、attempt_no、operation_id、quota_day、dispatch_class、计费频道ID、实际sender_uid、started_at/finished_at、effective_action、fallback_reason、正文、回复对象 ID/用户、status、failure_stage、脱敏 error_code、receipt、原请求是否仍未决；计费字段不可变，attempt_no 在计划内唯一 |
| 日容量账本 | 日期、类别、频道、动作的预留/尝试统计；可以索引查询实现，不强制增表；claim 时实际尝试必须原子持久化 |
| 计划事件 | 计划 ID、事件类型、时间、周期号、失败阶段/脱敏码、变更前后状态、理由/证据；包括准备读取失败、周期重排、人工确认和取消，不伪造写attempt；禁止存 Cookie/API key |

计划主要状态：`scheduled`、`waiting_template`、`paused_channel`、`claimed`、`succeeded`、`uncertain`、`manual_review`、`cancelled`。重试作为 scheduled 的新周期，逾期为派生属性，不单独覆盖终态。所有状态转移事务化；写操作前 claim 与 attempt 创建同事务，单进程串行发送。服务重启始终暂停，遗留 claimed 转 uncertain。

数据库实例独占锁必须在构造 Store、迁移、恢复 claimed 或修改运行设置之前取得，且覆盖整个实例生命周期；失败启动不得修改数据库业务状态。锁以规范化绝对数据库路径标识（含Windows大小写/路径别名处理），不能仅靠TTL/心跳过期接管仍存活或暂停的拥有者。只有确认原拥有者已退出并完成恢复条件检查才能接管；遗留桥接调用仍可能提交时，相关计划维持 uncertain。P1需选定并验证Windows支持的锁实现，不以普通“锁文件存在”或随机端口作为可靠独占证明；P2用两个真实本地测试进程验证，不连接真实平台。

| 当前状态/事件 | 合法转移与发送事实优先级 |
| --- | --- |
| scheduled/waiting_template，频道停用 | paused_channel，保存待恢复状态；重试任务也暂停，不管是否已有历史attempt |
| paused_channel，频道恢复 | 回到原非终态状态/原周期日期，重新校验其他阻塞条件，不自动恢复全局运行 |
| 尚未claim，频道删除 | manual_review并标orphaned；快照/去重保留，禁止自动发送 |
| 尚未claim，明确取消 | cancelled并留痕；不再自动建立新计划 |
| claimed，停用/删除/取消 | 标记对应阻塞或cancel_requested，不把在途事实改成“未发送”；禁止后续写入，等待归档原结果 |
| claimed或uncertain，收到可信成功 | 原attempt记录成功，计划succeeded；取消请求/孤立状态不能遮蔽成功事实 |
| claimed，收到明确未发送失败 | 归档失败；cancel_requested则cancelled，orphaned则manual_review，频道停用则paused_channel并保存重试周期，其余scheduled新周期 |
| claimed，结果不可判定/重启 | uncertain；孤立/取消只阻止未来尝试，不删除原attempt/额度/未决标记 |
| uncertain，人工确认未发 | 只有请求结束屏障和未发送证据成立，才可重新安排；孤立频道和账号未验证仍阻止执行 |
| succeeded，任何停用/删除/取消/重搜 | 保持成功与全局去重；禁止重排；可附加人工事件 |

同一计划的状态版本、准备结果版本及账号会话代数要在异步回调和claim前复核。迟到成功作为发送证据追加/归档，不用普通CAS失败静默丢弃；除此之外过期回调不得覆盖更新的人工操作。

迁移按以下默认策略，绝不清空原库：

| 旧记录 | 迁移行为 |
| --- | --- |
| succeeded | 成功计划及历史尝试，永久保持去重 |
| claimed / uncertain | uncertain，禁止自动重发 |
| failed | 历史尝试保留；旧错误缺少证据，不自动假定未发，转人工核查 |
| queued | 保留原动作和日期，读取迁移时可用模板生成一次候选池快照，标记 `legacy_snapshot`（不是历史原模板）并转待人工迁移确认；确认后才能发送，不重新抽取动作 |
| skipped / 仅 discovery | 保留历史去重，标记旧规则忽略；不自动批量转成 70%延后任务，人工选择后再建立计划 |
| 无频道或无模板的旧记录 | 保留、显示缺失原因并转人工状态 |

迁移必须保留旧记录中可确定的尝试日期、实际动作和次数，用于当天已用额度，不能因新表启用而刷新额度；旧计费类别不明时不可假装known，保守计入当日总额度及逾期已用份额并作为未知分类显示，防止未知历史释放额度。旧账号归属未知的可执行任务须人工确认归属及迁移快照后绑定已验证UID，历史尝试UID未知则永久保留unknown。

schema 升级原子完成、失败回滚、重复启动幂等。执行正式升级前维护者在停止服务后使用SQLite一致性备份，或者经过验证的SQLite备份接口；不得只复制仍在WAL模式运行的主文件。开发测试只用合成旧数据库，不读取/复制实际私有库。升级应用后保留旧表或可恢复副本，不能直接用旧版本程序操作新结构。

直接恢复迁移前备份只允许升级后尚无新增写尝试的回滚窗口。已有新增成功、明确失败或uncertain时，必须先一致性保存升级后数据库及增量发送/去重/额度账本，并经验证地合并到可兼容数据结构；做不到就禁止恢复旧备份后自动发送，采用向前修复。恢复备份不能消除已经在平台发生的写入，也不能刷新当天已用额度。P7交付明确回滚窗口与恢复步骤。

停用频道暂停其所有尚可继续的任务，包括已有失败历史的重试任务，恢复后按原日期继续。删除频道保留任务及所有去重信息，尚未在途任务转孤立人工状态；在途、uncertain和成功任务按上方状态表保留发送事实。频道名称/模板快照仍可显示，不因 ON DELETE / JOIN 消失。不自动绕过频道删除继续发送。

## 5. 界面与验收要求

任务列表提供来源、原动作、实际动作、模板候选池快照、首次入池、当前周期、日期、逾期天数、状态、失败次数、最后原因；分页查询，不全量装入前端。提供搜索暂停/恢复、频道暂停、计划取消、人工核查与确认迁移入口，操作显示明确结果与错误。

仪表盘分开显示搜索返回/匹配/重复/新增、成功数量、写尝试数量、剩余额度、逾期配额、待处理/溢出/结果不确定/需人工处理数量。剩余额度以 attempt 计算，不以成功评论数计算。历史展示按 effective_action，计划统计按 planned_action，避免回复降级后的报表失真。

核心验收：新搜索无日期和播放量过滤；不匹配不持久化；一个视频仅一个有效计划；70/20/10 与 80/20 边界正确且重启不抽签；日期容量和逾期规则正确；快照独立于模板修改；confirmed failure 能跨周期恢复；uncertain 无自动重试；所有阶段遵守额度/间隔/暂停；旧数据不丢失；未调用真实账号或 AI 服务。

详细执行步骤与预期见 `测试用例.md`；开发不可破坏约束见 `开发约束.md`。

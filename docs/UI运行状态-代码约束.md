# UI 运行状态显示改进：代码约束

状态：评审修订稿 v2，独立复核通过，供用户审阅。基线：Git `2763740`。
对应文件：`UI运行状态-开发计划.md`、`UI运行状态-测试与验收.md`。
本轮只写文档；以下约束用于未来开发，不授权当前变更服务。

## 1. 范围与业务不变量

C01. 常规范围仅修复观察层和交互可达性；S0a是明确单列的现有启动/暂停控制竞态前置修复（见C34）。搜索参数、关键词顺序、概率、模板快照、周期、选取顺序/扫描窗口、额度、互动间隔、读取预算、失败/不确定恢复语义不变。
C02. 禁止新增自动发评、自动核实、自动续跑或强制重发功能。每次重启保持暂停；风控/未登录/账号不符沿用失败关闭。
C03. BV/AV去重、claim先于外部写、attempt身份与额度不可变、迟到成功与uncertain屏障保留；不能因页面显示问题清库或删尝试历史。
C04. `GET /api/state`、摘要和详情不得执行B站/模型调用，不写任何表，不消耗随机数、读取额度，不调用Store构造函数，不排程或释放任务。判断可共享纯函数，副作用仍只在原执行路径发生。
C05. 所有全局/动作/频道额度、逾期份额、单计划与全局读取预算必须与当前执行条件同源；提炼只读helper前后以相同fixture比较bool、时间与外部调用轨迹。发现原业务缺陷单独提案。

## 2. 状态与时间的真实性

C06. 当前操作、控制状态和下一次安排分层。当前operation为事实，不用下一次排程反推；搜索/互动独立解释且说明串行，不把一个通道退避伪装成整个程序暂停。
C07. `phaseSince`只在实际operation id或阶段改变时更新；相同等待状态重复采样不能重置。普通等待阶段不在首页显示秒表。
C08. 时间类型必须区分scheduled/eligible/check/manual/unknown；eligible仅是已知条件下最早可尝试，不代表保证发送。人工阻塞为null时间，不伪造00:00或负数；配置额度0不得仅因日界重置承诺自动恢复。
C09. requestInFlight=true仅说明原请求结束尚未确认。与本地HTTP请求中、MCP运行中、uncertain=false分开；超时/not_found/重启或评论不可见不证明远端未发送。
C10. uncertain且原请求已结束只阻止该任务自动重发；若全局写屏障仍有效则明确影响其他写入。搜索继续与否必须据其真实独立条件，禁止通用“其他任务继续”固定文案。
C11. 当前本地操作的开始/结束受token/id约束，finally只清自己的operation，晚到回调不能覆盖新的暂停原因或新操作。正常顺序暂停等待在途结束的执行语义不变；真实控制竞态按C34修复，不能只修状态文本。
C12. 不通过匹配中文错误字符串新增可靠性判断；新结构化原因在实际决策点产生。旧pauseReason保留兼容，可用受限映射并有“暂停原因待核对”兜底，不能猜出新事实。
C13. 快照使用单一serverNow与同步只读采样；加schemaVersion/instanceId/seq，前端保护乱序与重启。状态读取不记录Activity或持久化seq。重复状态读取不触发setStatus写循环。
C14. 固定业务日Asia/Shanghai，与浏览器/宿主时区无关。前端使用服务端锚点+performance.now，整点到达显示“正在重新确认”，不能在倒计时到0时自行触发业务操作。
C15. 请求等待预算来自可证实调用契约，不能把tool 45秒当connect+tool整个操作保证；不得为展示而新增取消/重试真实发送逻辑。

## 3. API、查询与性能

C16. 新契约集中在server/model.ts，共享Zod类型；/api/state兼容旧字段，前端明确识别旧后端而不报成服务停止。旧runtime保留时需与新display在同一快照保持可解释，不得同时显示两套冲突结论。
C17. 首页近期计划、attention单独按状态/业务排序查询，不能在旧plans前200条内筛选。总数覆盖全队列；展示最多3条近期计划和有限人工事项，不能拉全库到前端。
C18. 当前执行仍看既有100条窗口；窗口外可执行任务只能标“尚未进入本轮选择”，不能越过原窗口改变调度。摘要扫描必须有界并注明信息不足；不能把limit内的空结果说成全库无任务。
C19. 不允许每任务调用topics()再统计所有频道，避免摘要N+1。聚合每日额度/读取预算/最新attempt一次读取并复用；大队列用query plan与基准验证。必要索引属于schema变更，先补兼容/回退计划。
C20. 响应不得泄露Cookie/刷新令牌/模型key、完整桥接错误或模板正文。当前视频与少量公开元信息可显示；人工详情保留现有已授权字段。测试使用合成秘密marker验证值不外泄，不以apiKeyConfigured字段名判断泄露。

## 4. 前端可用性与人工处理

C21. 首页默认一句主状态、双通道、按需处理卡、三条近期任务；技术字段和完整原因列表放详情，首页不堆所有原因。状态不能只靠颜色，长标题与窄屏不能遮挡入口，信息不靠悬停才能获得。
C22. currentDueAt取当前持久化dueAt，不虚构不可变的首次排程；当前排程已到但被冷却/额度阻止时必须解释原因，不写“等待计划到期”；已到执行时间与超过30天未完成分开，详情保留精确截止日/溢出规则。
C23. 请求单飞、有限超时、取消旧请求、保护旧响应；前台快照过期>15秒必须标识，断线保留历史但停止可执行承诺。离线不是证明服务已停止，不能显示旧绿色“巡逻中”冒充实时状态。
C24. 前台恢复立即重新同步，旧实例响应不能覆盖新实例；未知契约显示“需要刷新/升级页面”。任何计时器、事件监听、请求在卸载时清理。
C25. 直达链接支持`/plans`查询参数、刷新/前进后退/跨页ID。未找到、已处理、旧版本、请求失败均有中文反馈；不能因id不在当前页就清空选中。
C26. 核查按钮严格沿用后端身份、requestInFlight与attempt状态校验；详情刷新但不得覆盖未保存模板草稿；人工操作前获取新鲜详情，失败不静默吞掉。不新增一键“清空不确定”或无需证据的重试。
C27. 展示TSX提取到无CSS副作用、无document/localStorage顶层访问的模块，web/main只装配；SSR用现有react-dom/server而不是直接导入挂载入口。不把DOM/SSR输出断言当成浏览器定时器、路由、焦点或断线交互测试；这些需可控浏览器验收。无可用浏览器时明确列为未验收，不通过手写模拟所有Hooks来冒充实际React行为。

## 5. 工程与交付

C28. 先读AGENTS及对应文档；如旧业务条款冲突按用户已确认的新策略限定覆盖，其他边界保留。沿用TypeScript strict/ESM/.js导入，不直接编辑build-server/dist，不升级依赖或触碰vendor。
C29. 测试只用临时/内存SQLite、Fake Bilibili、固定时钟、分别固定Store与Scheduler随机源和延迟Promise；真实环境写开关false；生产createApp(...,false)的拒绝测试与Fake允许态分别验收。纯Fake专用工厂可在进程内传true测试HTTP按钮，但禁止创建McpBilibili、启动Python或连外网，post只记Fake日志，不得修改真实环境写锁。调度器直接run不算HTTP验收。不读取/复制私有库、凭据、备份，不自动登录、调用模型或发送评论。
C30. 纯展示无需新持久化；若不得不迁移，先补计划、事务/幂等/重启/回退测试并审阅。不能用数据库重置掩盖问题。
C31. 新增回归必须运行且零失败；不得以skip掩盖新需求。历史跳过数量单列。门槛npm test、npm run lint、npm run build；bridge不改时不要求借机重写Python用例。
C32. 继续按用户已授权的每阶段提交/普通推送，不强推、不伪造作者、不触碰凭据/Git全局身份；身份缺失先查当前用户授权信息，不能沿用上游作者冒名提交。
C33. 文档编写/评审与实施分离。本轮不修改源代码/测试/构建产物，不提交或推送，不暂停/启动服务，不修改正在运行的状态；后续交付报告列出实际验证与未验证事项。

C34. S0a单独修复run/pause竞态：控制序号在入口确立，所有await后/修改running前复核；旧启动、catch/finally不能越过后续暂停；run启动校验纳入操作生命周期。禁止自等待死锁，正常顺序和在途发送规则不变。若未授权该前置项，UI可独立开发但必须保留已知失败结论，不能skip后宣布完整验收。
C35. 今日成功沿用现有startedAt的上海自然日、status=succeeded、effectiveAction；迟到回执/人工确认只回补原发起日，不按finishedAt重复计入今日。额度仍按原attempt计费不变。
C36. 全局写屏障与Store.anyRequestInFlight()一致检查所有attempt，不限最新条；已结束的单条uncertain不应伪造全局暂停。所有可证明原因留在API，首页仅主原因和必要补充。
